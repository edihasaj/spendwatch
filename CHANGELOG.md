# Changelog

## Unreleased

- Count a gateway-routed turn once. A subscription gateway bills a Codex turn on a Copilot or Claude subscription while the Codex rollout records it again, so a routed month read high by exactly the turns the subscription paid for. Spendwatch now reads the gateway's month ledger (`<state>/usage/usage-YYYY-MM.jsonl`, found through `$SPENDWATCH_GATEWAY_STATE`, the gateway's own `stateDirectory`, or its default beside the gateway config; `$SPENDWATCH_GATEWAY_SOURCE=off` skips it, and an explicit config enables it only with a `gateway` root). A gateway row carrying a `resp_gl_*` response id is the billed record, so the rollout's copy of that response is dropped when this Mac's ledger holds the row; a rollout turn with no row of its own claims a matching telemetry row — same model, same gross input and output tokens, within 30 seconds — and is dropped the same way. Telemetry rows are the gateway's one-time import of its request history from before the ledger existed; `session: false` rows come from clients with no Codex session, so they count directly, and `session: true` rows count only once a rollout claims them. Rows are keyed by `host:requestId` so one call recorded twice still counts once. Copilot rows are priced with their reported AI credits and labelled for what they were (`(partial credits)`, `(unpriced)`, and for an imported row `(telemetry backfill)`, `(telemetry backfill, partial credits)` or `(telemetry backfill, unpriced)`, which keeps the credits it carries); Claude rows have no credit figure and are priced from their tokens under the model alias. Codex and self-hosted rows are ignored, the gateway's rows appear inside the Claude and Copilot tabs under the `gateway` project, and rollouts are always read before the ledger so every claim lands first. Codex profiles are now also read from `~/.codex*/archived_sessions`, deduped by rollout name against the live copy. Codex counting changed for every user, gateway or not: calls are read per response from `token_usage_record` (falling back to `token_count` for rollouts without one), a `token_count` that repeats the previous one is no longer billed twice (about 6% fewer calls on one month measured with no gateway at all), and `cache_write_input_tokens` is taken out of the input and priced as cache writes. Both spend archives now compare `observed_calls` rather than billed calls, so a month that was deduped — its `calls` fell while it still saw every turn — keeps its full month instead of being replaced by a thinner read; `calls` can sit below `observed_calls` because of repeated `token_count` events as well as routed turns, so the pair says nothing about routing on its own. Check one with `SELECT source, calls, observed_calls FROM spend_report WHERE month='2026-10' AND source LIKE '%:codex%'`.

- Keep the gateway ledger correct in `watch`, across time zones and in the archive. `watch` found each rollout again on every tick with a fresh parser, so a routed turn that arrived after the first tick was billed by the rollout as well as by the ledger; a file now keeps its first parser state and only takes the reloaded ledger from each discovery. The ledger's month files are named by UTC month, so the window that picks them is now UTC too: east of UTC the previous UTC month holds the first hours of the new local month, and those turns used to vanish. A `token_count` that has no response id (a Codex build without `token_usage_record`) can now claim a matching billed gateway row as well as a telemetry row, instead of billing the turn twice. The spend archives record whether the ledger was read (`ledger`), so switching the gateway source off no longer double counts routed turns across sources (the rule is now the `routed_calls` guard below).

- Close more ways the gateway ledger could count a turn twice or lose one.
  - Archive: a read without the ledger no longer raises the daily token rows of a month archived with it (the rows were maxed even though the month was rejected), and a month whose every call was routed (`calls` 0, `observed_calls` above 0) is now archived, and kept in the multi-month `--json` payload, so it replaces the older read that billed those turns in Codex.
  - State directory: the gateway config's `stateDirectory` is resolved as the gateway does, relative to the config directory and `.state` when missing, instead of against Spendwatch's working directory. `gateway init` writes `.state`, which used to find no ledger while still dropping every `resp_gl_*` turn from Codex. `SPENDWATCH_GATEWAY_CONFIG` names another gateway config; `GATEWAY_CONFIG` is deliberately ignored.
  - `watch`: a Codex rollout moved into `archived_sessions` while watched is no longer read again from the top and billed twice, because a rollout now keeps its identity by file name. A `token_count`-only call that lands one tick before its ledger row is billed once, by the rollout, instead of by the rollout and the ledger.
  - `--agents claude` and `--agents copilot` read the Codex rollouts for claims when telemetry rows are waiting for one, so they show the same Claude and Copilot spend as the full report; an `--account` filter keeps those claims too.
  - Copilot rows imported from telemetry keep the credits they carry (`nanoAiu / 1e11`, partial respected, labelled `(telemetry backfill)` or `(telemetry backfill, partial credits)`); only a row with no credit figure stays `(telemetry backfill, unpriced)` at $0. A Claude row is attributed to the account signed in under its provider's `authDirectory` instead of always the default account.
  - Documentation: `calls` below `observed_calls` is no longer read as a sign of routing, telemetry rows are described as the gateway's one-time import, only Codex rollouts are deduped, and the README explains how several Macs share one ledger (corrected in the next entry).

- Count a routed turn only where a ledger proves it is counted, and keep the archive's sources in step with each other.
  - A Codex rollout drops a `resp_gl_*` call only when this Mac's ledger holds the gateway row with exactly that response id. Before, any Mac whose Spendwatch loaded a ledger — even an empty one, or none at all — dropped every marked call, so a turn served by a Mac that does not run Spendwatch, a ledger month pruned after 13 months, or a misplaced state directory lost turns silently. Such a call is now kept in Codex as `<model> (gateway-routed, not in this Mac's ledger)` and the report says so. A turn another Mac's gateway served is therefore counted on the client's Codex tab, labelled, and again on the serving Mac's Copilot or Claude tab if that Mac runs Spendwatch: the rollout records no serving host, so Spendwatch alone cannot prove which. A state directory without a `usage` directory is no ledger.
  - The archive records `routed_calls`, the routed calls a read billed through the ledger, and a read that billed fewer never replaces one that billed more; this replaces the `ledger` guard. The first time a month's Codex, Claude and Copilot reports take a read with routed calls while any holds a read without the ledger, they change together or not at all, so a refused Claude read (rotated transcripts) can no longer make Codex lose its routed turns, and a refused Codex read can no longer leave them counted twice.
  - Copilot gateway rows go to the account their provider signs in under: `lastLoggedInUser.login` in its `authDirectory`'s `config.json`, or the directory name when no login is recorded, in a stream of their own, as Claude rows already did.
  - A forked rollout takes its provider, model and session id from its own `session_meta`, not from its parent's, which the fork copies in after it. A fork that crossed providers would otherwise have its routed calls judged by the parent's provider. Each fork now also counts as its own session instead of merging into its parent's: on one Mac, 96 of 468 October rollouts were forks, and the October Codex session count rose from 382 to 453 with calls and cost unchanged.
  - The ledger files a window reads reach 30 seconds before it, so a call filed at the very end of one UTC month is still matched when its rollout line, in the next month, is read with that month alone.
  - Reading the ledger is linear: rows were regrouped per row, account labels re-read a credential file per row, and every claim scanned the whole ledger, so 40,000 rows took about 3 seconds and `watch` fell behind its 2-second tick. 100,000 rows now load and group in about 150 ms.
  - `watch` applies `--account` and `--project` on every tick, not only on the first read, so another account's rollout no longer joins the Codex total; it counts lines written after it started, which a window that closed at start dropped; it no longer loses a line that was half written when it started; and it replays each rollout's claims on the reloaded ledger, so a claimed row is not handed to a second call.
  - The warning for routed rollouts that record `token_count` without `token_usage_record` is shown under the report even when Codex reported calls, which is the only time it applies.
  - A provider type or provider name such as `toString` is no longer mistaken for a subscription, and Codex's `token_usage_record` is read only under the field names Codex writes.
  - Tests no longer read the gateway installed on the machine running them.

- Fit the capacity page to phone screens. Below 480px the source list is now a two-column grid with the device name above its status, so stale labels no longer wrap at different points. The last cell of the pace legend now spans the full row instead of leaving an empty cell. The Cycle column in each utilization card gets the most room, because it holds the longest value. On wider screens, a long "Updated … · device + device" line no longer squeezes the account name and email into a one-letter column. That line now wraps, and the source list wraps inside its row instead of pushing the page wider than the window.

- Track pi and oh-my-pi alongside Claude Code, Codex and Grok. Sessions are read from `~/.pi/agent/sessions` (or `$PI_CODING_AGENT_DIR/sessions`) and `~/.omp/agent/sessions`; oh-my-pi is a fork that keeps pi's format, so one parser reads both. Every assistant message carries the usage of its own model call and is billed on its own, as are calls made outside the conversation: cache warming, compaction and branch summaries, and oh-my-pi's `model_usage`. Branching keeps abandoned paths in the file, and those calls were paid for too, so they count. The project comes from the cwd in the session header, because the folder name flattens every separator to `-`.

- Price self-hosted models at zero on purpose. `qwen3.8-flash-next` served by vLLM on your own hardware has no per-token bill; it was already free as an unknown model, and is now listed so the zero is deliberate. Its tokens still count.

- Keep the Add account panel closed once it is closed. A sign-in link or a cross-page Add account link leaves `#setup` in the URL, and the panel reopened on every later load however many times it had been dismissed. Closing it now clears that hash, so only an explicit click reopens it.

- Read the Claude credential that a login actually wrote, not whichever Keychain item matched first. Claude Code leaves the previous item behind when it re-creates one under a different account name, and `security find-generic-password -s "Claude Code-credentials"` returns an arbitrary match: an orphan whose token expired on 9 September shadowed the live credential for a week, so every capacity read came back HTTP 401, the card sat on a sign-in banner, and the account finally aged off the dashboard altogether. Every item for the service is now read and the unexpired one with the furthest deadline wins, falling back to the plain lookup when the Keychain cannot be enumerated.

- Name a project from the working directory the session recorded instead of the folder Claude stored it under. That folder name has every `/` flattened to `-`, so one project arrived under several names — `tg/payroll-backend` and `tg-payroll-backend`, `dayshape/dayshape` and `dayshape-Dayshape` — and its spend was split between them. Every parser now shares one naming pass: a path stops at the checkout that contains it — located by its `.git`, so `spendwatch/src` is `spendwatch` while `oss/paseo-baseline` keeps both segments — worktrees collapse into the directory holding them rather than inventing a project per generated name, scratch under a hidden directory is credited to the repository around it, dated scratch to the tool that made it, every temporary directory becomes a single `/tmp` entry, a directory stamped with an epoch (one run of a tool, named afresh each time) becomes a single `~/scratch` entry, and spellings differing only in case are folded together since the filesystem never distinguished them.

- Keep an all-time spend archive rather than only the months still on disk. Each recorded month now also stores where its tokens went, so a month card shows who spent it and which projects it went to, and the History tab leads with the all-time token and cost total. `--months N` backfills as far back as the transcripts reach; a month holds the agents whose transcripts still existed when it was first recorded, which is stated on the page rather than implied.

- Reset spend with the calendar month and keep every closed month. A report covers the current month by default, `--month YYYY-MM` reads a past one, and `--days N` still gives a rolling window. The History tab lists one collapsed card per month with its tokens, estimated cost, calls, sessions, and per-machine breakdown, so an expensive August stops inflating a quiet September.
- Window turns by their own timestamp instead of the mtime of the file holding them. Sessions are found by file mtime, so resuming an old session pulled every turn it ever recorded into "the last 30 days" — a 30-day total could quietly cover 37 days of work. `--months N` now also folds several months out of a single pass, and each report records the month it belongs to so per-machine exports merge into the right one.

- Refresh the Claude OAuth token instead of waiting for a human. The access token lives eight hours and no collector host runs Claude Code, so the capacity card reliably died within a working day and only a manual `claude login` brought it back. Reads now refresh ahead of expiry, retry once after a 401, and persist the rotated credentials atomically. Credentials written without an `expiresAt` are treated as due, which is the shape that used to go stale unnoticed.
- Report why a Claude capacity read failed instead of returning an empty array. An expired token, a rate limit, and a transient fault were indistinguishable, so an account that needed re-authentication looked exactly like an account that was never configured. `capacity-current --provider claude` now names the reason on stderr, and an expired token raises the existing sign-in banner rather than letting the card drift into "Not current".
- Fall back to the macOS Keychain when `~/.claude/.credentials.json` is present but blank. Claude Code leaves that husk behind after moving the secret to the Keychain, and preferring the file whenever it merely existed dropped the account with no usable token and no explanation.
- Show Grok on the capacity dashboard after the Lokai routes. Grok Build reports no quota and no balance, so the card reports what was sent over a rolling 24 hours and 30 days, priced at published list rates as an API-equivalent estimate rather than billed money, and stays out of the utilization planner.
- Track Grok CLI spend alongside Claude Code and Codex: read `~/.grok/sessions/**/updates.jsonl`, attribute tokens to the prompt that caused them, and break the run down by tool, shell command, project, and model. `~/.grok-*` profiles and the account email are picked up automatically, and `spendwatch account add grok --name <profile>` connects another one.
- Read live Claude capacity through the account's own OAuth usage endpoint (`capacity-current --provider claude`), removing the third-party menu-bar dependency that could silently freeze Claude windows on an old snapshot.
- Measure the recent burn rate inside the current quota cycle and compare it with the rate the remaining allowance affords, so a burst is visible while there is still time to slow down. Each window now shows its pace, its budget multiple, and how long before the reset it runs out at that rate.
- Never present an expired or unrefreshed quota sample as current capacity: the dashboard labels it "Cycle ended" or "Not current" with the last reading and its age, the terminal summary matches, the utilization planner stops pacing it, and `guard` returns `unknown` instead of `ok`.

- Fill the Copilot budget track solid red once the monthly ceiling is passed instead of draining it to an empty line.
- Report Copilot overspend past the monthly ceiling instead of clamping it, and alert on the monthly credit budget at the same 30/15/10/5/0 steps as weekly quota.
- Pace Copilot against a manual monthly ceiling of 40,000 AI credits for $400 ($0.01 per credit, overridable) and drop the per-seat shared-pool and promotion maths.
- Remove the private dashboard hostname from the public Chrome extension, add origin-scoped URL configuration, and enable repository security automation.
- Add a 90% utilization planner for subscription-backed capacity, excluding PAYG API balances from subscription sizing.
- Match Chrome's native dark bookmark bar and menu typography, sizing, colors, and surfaces.
- Show the Chrome profile's Bookmark Bar on the extension New Tab page.
- Add a self-recovering Chrome New Tab extension for the private capacity dashboard.
- Hide the alert test control after the first verified push delivery.
- Show provider-aware sign-in links when a collector reports expired authentication.
