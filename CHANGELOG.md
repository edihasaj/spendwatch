# Changelog

## Unreleased

- Stopped double counting older forked Codex subagent rollouts. Turns whose id
  the actual parent rollout also opened are skipped; child-only turns still
  count, and a fork without a readable parent is counted whole with a warning.
  A context-only paginated rewrite yields to its complete legacy original, and
  duplicate copies that differ only by a turn label, extra user or developer
  messages, or repeated usage readings no longer block selection. Thanks to
  @edihasaj for the Studio history investigation.
- Fixed missing Codex history from compressed native archives and reconciled
  plain and compressed rollout copies before counting usage. Trusted captures
  remain available when a replacement has unresolved coverage, with separate
  downloads for comparison. Retained isolated Claude clients now contribute
  their recorded usage without inferring a historical account from today's
  login.
- Corrected Codex account history using matching gateway evidence and reduced
  managed capacity query work so incoming snapshots can keep up. Thanks to
  @edihasaj for reporting and investigating the accounting discrepancies.

- Added optional managed PostgreSQL serving and independently verified history
  archives while retaining native SQLite for the local CLI. Thanks to
  @edihasaj for the database migration and recovery qualification.

- Add Mission Runtime and AutoReview as sources. Both agents leave no transcripts, so Spendwatch reads the `agent-usage.v1` records they write about their own usage (`src/agent-usage.ts`): gross input minus cached and cache-write tokens is the uncached input, output already includes reasoning, and a reported `cost_usd_micros` is the call's cost. Each attempt and model is one call, so a rewritten (larger) record replaces the last read and is never counted twice.
  - `mission` reads the `usage:*` rows of `mission_run_outputs` in Mission Runtime's authority SQLite store, read-only (`~/Projects/mission-runtime/.mission-runtime/authority.sqlite`, `$MISSION_RUNTIME_DB_PATH`, or a `mission` config root), with the run's repository as the project (only `json_extract` of the repository key is read from the spec). A store with no `-wal` (Mission Runtime removes it on a clean close) is opened as immutable, and a store that exists but cannot be read is reported as a note instead of nothing. A Mission Runtime record is dated at the run's start (`mission_runs.created_at`, else its last update), so an attempt running past the 1st stays in one month and a history archive does not count it twice; the window still selects rows by last update. `autoreview` records are dated at their last update. `autoreview` reads a JSONL job ledger named by an `autoreview` config root, the last line of an attempt winning; it has no default location, and `--agent autoreview` without a root says what is missing. Both honour `--project`.

- Count Harness Gateway Messages usage once. From gateway 0.4.4 the gateway also serves native Anthropic Messages clients such as Claude Code, and it marks those calls `msg_gl_<id>` instead of `resp_gl_<id>`. Spendwatch knew only `resp_gl_`, so it ignored every Copilot and Claude-subscription ledger row written for a Messages call, and it priced Claude Code's transcript copy of the call as ordinary Claude usage, under the wrong vendor and without Copilot credits.
  - Both prefixes are one marker family, each followed by the same gateway request id, and either is accepted wherever a marked id is matched: the ledger's billed rows, Codex records, Claude Code transcripts, and the settling of several Macs' reports.
  - A Claude Code message whose `msg_gl_` id this Mac's ledger holds is dropped from the Claude transcript, and the ledger row bills it with its vendor, model and Copilot credits. The message's lines wait for the row as a Codex record does, counted from when the line was read rather than from its stamp (Claude Code writes a reply's lines when the reply ends but stamps each with the time its block began, up to a minute earlier), so `watch` and a report bill each call once even when the transcript is read before the gateway appends the row, and a row that lands late never bills a call the transcript already billed. A message that no ledger on this Mac holds is still priced as Claude usage, labelled `<model> (gateway-routed, not in this Mac's ledger)`, and it is taken out wherever its report meets the report of the Mac that served it.
  - A `msg_gl_` row is matched only by its id, never by model, tokens and time, so a Codex `token_count` is never dropped against the row of a Claude Code call.
  - A Claude Code transcript that `--project`, `--account` or an `--agents` subset leaves out is still read for its ledger decisions, as a Codex rollout is, so a filtered report bills a late `msg_gl_` row the same way as the full report. `src/sources.ts` moved its gateway helpers into `src/gateway-sources.ts`.

- Count a turn that a subscription gateway routed once, on the Mac whose gateway served it. The gateway bills a Codex turn on a Copilot or Claude subscription while the Codex rollout records it again, so a routed month read high by exactly the turns the subscription paid for.
  - Spendwatch reads the gateway's month ledger, `<state>/usage/usage-YYYY-MM.jsonl`. The state directory comes from a `gateway` root in an explicit config, `$SPENDWATCH_GATEWAY_STATE`, or the gateway config's `stateDirectory` (resolved as the gateway resolves it; `$SPENDWATCH_GATEWAY_CONFIG` names another config, and the gateway's own `$GATEWAY_CONFIG` is deliberately ignored). `SPENDWATCH_GATEWAY_SOURCE=off` skips it, and an explicit config enables it only with a `gateway` root. Month files are picked by UTC month, as the gateway names them, plus the 30-second claim window before the period.
  - A gateway row with a `resp_gl_*` response id is the billed record. A rollout record with exactly that id is dropped when this Mac's ledger holds the row. A marked record no ledger on this Mac holds is kept in Codex as `<model> (gateway-routed, not in this Mac's ledger)`, and the report says so. Because the gateway appends its row just after the response ends, such a record (and a `token_count` that could match a billed row) first waits for the row: `watch` checks it on each tick, a report reads the rows appended since it loaded the ledger, and only a call with no row within 30 seconds, or at the end of a report, is billed from the rollout. A row that arrives later never bills it a second time.
  - A Codex report lists each marked call it kept by its gateway request id, and a Copilot or Claude report lists the ids it billed from its ledger. Where several Macs' reports meet — `report --input`, the reports and monthly history of the spend archive, and `spendwatch tokens` — a client's call that a serving Mac's report billed is taken out of the client's Codex totals, model, account, project and daily token rows, so it is counted once, on the serving Mac. `report --json` passes the reports on unsettled, and a client turn that no collected report billed stays in Codex.
  - Telemetry rows are the gateway's one-time import of its history from before the ledger existed. A `session: false` row counts directly. A `session: true` row counts once a rollout claims it, with the same model and the same gross input and output tokens within 30 seconds, and the rollout's copy is dropped. `--agents claude` and `--agents copilot` still read the Codex rollouts for those claims, and an `--account` filter keeps them. Rows are keyed by `host:requestId`, and the gateway's own row wins over its telemetry echo.
  - Copilot rows cost `nanoAiu / 1e11` dollars and are labelled `(partial credits)` or `(unpriced)` when the credits were partial or missing; imported rows add `(telemetry backfill)` and keep the credits they carry. Claude rows are priced from their tokens under the model alias. Codex and self-hosted rows are ignored. Gateway rows appear in the Claude and Copilot tabs under the `gateway` project, under the account the provider signs in with (its `authDirectory`, or the default login), one stream per account. The account-wide Copilot meter is unchanged and stays the only Copilot total.
  - The spend archives record `observed_calls`, `routed_calls` and `ledger`. A read replaces a stored month only when it observed at least as many calls and billed at least as many routed calls through a ledger, so a deduped month keeps its full month, and a read with the source switched off or a pruned ledger month cannot bring routed turns back into Codex. The first time a month's Codex, Claude and Copilot reports take a read with routed calls while any of them holds a read without the ledger, they change together or not at all, and a refused read leaves the daily token rows alone. A month whose every call was routed (`calls` 0, `observed_calls` above 0) is archived and kept in the multi-month `--json` payload. Archives written before these columns still load.

- Bill every routed call exactly once in `watch` and in a report, also for `token_count`-only rollouts, calls whose tokens match, and rows that arrive more than 30 seconds late. A claim now takes the free ledger row nearest in time to the call, not the oldest in the window, and when every alike row is taken the calls standing on them step to another free alike row to leave one, so a call another Mac's gateway served no longer takes the row of a neighbour with the same tokens and leaves the neighbour billed twice. A call newer than the ledger read now asks the ledger for the rows appended since before it claims one, as it already did before being billed. A marked record dropped on the strength of its row now holds that row, so a `token_count` of the same size from another Codex build on the same Mac cannot be dropped on it too. `watch` reloads the ledger on every tick, and each rollout used to replay its earlier decisions only when that rollout was read, so the rollout read first could take a row another rollout's earlier call held and leave that call billed twice or not at all. A decision now remembers the row it held and its place among all decisions; every tick replays all of them together, in that order and on those rows, before any rollout reads a new line. A ledger or Copilot session stream now replaces what the last poll folded instead of adding to it, because a row can stop billing once a rollout's bill covers it. Seeded fuzz tests (hundreds of worlds per mode, for `watch` and for a report) pin it. A native Copilot session store is read once per tick for each session's version and events together, and its sessions 50 at a time, because the table has no index on the session: a store of 1,000,000 rows in 1,000 sessions took 60 s to read and 29 s per idle `watch` tick, and takes 3 to 4 s to read the first time (see the entry below for the idle tick). A store that cannot be read at a poll is skipped until the next one instead of stopping `watch`. Every test now makes its temporary directories through the shared helper, so a run of the suite leaves none behind (the note two entries below held only for the test files already converted).

- Bill every routed call once under the worlds that a seeded fuzz of whole Macs found, and say plainly what no ledger can tell apart. The fuzz (`test/gateway-fuzz-macs.test.ts`) runs one or two Macs, each with a records build and a token_count build of Codex, a gateway that writes rows late or never, a history import that echoes some calls, and forked rollouts, over many ticks of `watch` and mid-run reports; 81 to 241 of every 300 of its worlds failed before, and none of 16,000 does now.
  - A marked record whose row a `token_count` of the same size already stands on is billed as the plain call it is, without the gateway's id and without the label, so that settling reports against each other no longer takes it out against the very row that bills the other call (a `token_count` read before the record made one bill of two calls).
  - A fork's dropped and billed copies of one response keep their one bill when an alike call looks for a row: a search that fails now puts every row back exactly as it was, where it used to clear the mark that the billed copy had left. A response recorded in two rollouts is billed once even when neither copy found its row in time.
  - The search for a row to give a call has no limit of 100 rows any more, so a chain of alike calls longer than that no longer leaves a call billed twice, and it keeps its own stack, so a chain as long as the run does not overflow it. A search that fails remembers the rows it looked at until the ledger gains a row, so calls that find none do not each walk the same chain (100 such calls over 5,000 alike rows take 14 ms; each would take 10 ms without the memory).
  - `watch` bills a routed Copilot or Claude call when the ledger had no row for the account at the start (it used to show it in neither tab, and Codex dropped its own copy), and tags its reports as read from a ledger once the ledger exists.
  - A `token_count` whose own row has not landed takes a billed row before a telemetry row of the history import, and `watch` hands it to the best row again on every tick, so a history row near it no longer bills the call a second time when its own row lands.
  - A rollout that Codex files away outside the roots a config names keeps its decisions in the reloaded ledger, and the calls it left waiting for a row are still decided, so a row that lands later no longer bills a call again and a call waiting when the file moved is no longer lost.
  - The gateway's own row that replaces the telemetry echo of a call a claim already holds keeps that claim on the next tick, and the claim can still step aside for the call's own record.
  - An idle `watch` tick reads nothing from a native Copilot session store that has not been written to for two seconds (by its size and modification time and those of its write-ahead log): 3 s per tick for 1,000,000 rows in 1,000 sessions became 15 ms, and 300,000 rows went from 1 s to 15 ms. A session store whose read failed is read again, as a batch, by the next session instead of by a full scan for each.
  - `bun run build` removes the `.*.bun-build` staging files that `bun build --compile` leaves in the working directory (nineteen of them, about 68 MB each, sat in a checkout). It removes only the ones that build made.
  - The README lists the cases the ledger cannot resolve without an id on the call: a `token_count` whose own row is not in this Mac's ledger can stand on the row of an alike call, which is short by one until that call's record is read, or for good where its record is on another Mac's report; a `token_count` another Mac in the set served is billed by both Macs; and a report read while a new ledger imports its history can bill a `token_count` by an imported row and by its own. The fuzz allows exactly these and fails on anything else, and `SPENDWATCH_FUZZ_SEED` and `SPENDWATCH_FUZZ_SEEDS` replay one seed or hunt through more.

- Make the gateway ledger count each routed call once under every ordering of a read. A call a rollout billed because its ledger row had not landed yet is remembered by the ledger of that read, so a row that lands before a later rollout finishes is matched to it instead of being billed a second time (including a `token_count` with no response id). `watch` leaves a call younger than 30 seconds waiting on its first read too, draws nothing on a tick that finds nothing new, keeps routed Claude turns in the totals under `--project`, and prices `cache_write_input_tokens` of a `token_count` as cache writes. The spend archive leaves a month's daily rows alone for any read whose routed calls differ from the stored one, also when it routed more but observed fewer.

- Settle a routed call the same way however the run is limited, and refuse ledger rows no gateway wrote. A row that lands while the rollouts are read is now taken in for every vendor, so `--agents codex` no longer bills a Copilot call as `(gateway-routed, not in this Mac's ledger)` that the full report drops; a read that outlasts the 30-second claim window checks for the row before billing a call that has waited it out; and the gateway's own row for a call the ledger held only as a telemetry echo replaces the echo. A ledger row with a negative, fractional, infinite or absurdly large token count, no request id, or a time no date can hold (one such row made `watch` throw) is dropped, a cache count above its input is capped at it, and a negative or out-of-range credit figure leaves the call `(unpriced)`. `watch` now notices a ledger row rewritten in place at the same length, and also draws nothing on a tick that finds a native Copilot session store unchanged (a new row or a finalized charge still redraws). `SPENDWATCH_CLAUDE_ACCOUNT` joins `SPENDWATCH_COPILOT_ACCOUNT` to name the account outright, and an explicit config now decides where Gemini logs are looked for, as it does for every other agent; the test suite uses both, so it reads no real login or `~/.gemini`, and no longer leaves its temporary directories behind.

- Count Codex calls per response, for every user. Calls are read from `token_usage_record`, one per `response_id`, falling back to `token_count` for rollouts without records. A `token_count` that repeats the previous one is no longer billed twice (about 6% fewer calls on one month with no gateway at all), and `cache_write_input_tokens` is priced as cache writes instead of input. Rollouts in `~/.codex*/archived_sessions` are read too, once per rollout name. A forked rollout keeps its own provider, model and session id instead of its parent's, so each fork counts as its own session (one October rose from 382 to 453 sessions, with calls and cost unchanged).

- Keep `watch` correct as files grow. A rollout keeps its parser state across ticks, including after Codex moves it into `archived_sessions`, so a turn written after the first tick is still recognised as routed and a moved rollout is not read again from the top. `--account` and `--project` apply on every tick, lines written after `watch` started are counted, and a line still being written when it started is read whole once it is finished.

- Fit the capacity page to phone screens. Below 480px the source list is now a two-column grid with the device name above its status, so stale labels no longer wrap at different points. The last cell of the pace legend now spans the full row instead of leaving an empty cell. The Cycle column in each utilization card gets the most room, because it holds the longest value. On wider screens, a long "Updated … · device + device" line no longer squeezes the account name and email into a one-letter column. That line now wraps, and the source list wraps inside its row instead of pushing the page wider than the window.

- Track pi and oh-my-pi alongside Claude Code, Codex and Grok. Sessions are read from `~/.pi/agent/sessions` (or `$PI_CODING_AGENT_DIR/sessions`) and `~/.omp/agent/sessions`; oh-my-pi is a fork that keeps pi's format, so one parser reads both. Every assistant message carries the usage of its own model call and is billed on its own, as are calls made outside the conversation: cache warming, compaction and branch summaries, and oh-my-pi's `model_usage`. Branching keeps abandoned paths in the file, and those calls were paid for too, so they count. The project comes from the cwd in the session header, because the folder name flattens every separator to `-`.

- Price self-hosted models at zero on purpose. `qwen3.8-flash-next` served by vLLM on your own hardware has no per-token bill; it was already free as an unknown model, and is now listed so the zero is deliberate. Its tokens still count.

- Keep the Add account panel closed once it is closed. A sign-in link or a cross-page Add account link leaves `#setup` in the URL, and the panel reopened on every later load however many times it had been dismissed. Closing it now clears that hash, so only an explicit click reopens it.

- Read the Claude credential that a login actually wrote, not whichever Keychain item matched first. Claude Code leaves the previous item behind when it re-creates one under a different account name, and `security find-generic-password -s "Claude Code-credentials"` returns an arbitrary match: an orphan whose token expired on 9 September shadowed the live credential for a week, so every capacity read came back HTTP 401, the card sat on a sign-in banner, and the account finally aged off the dashboard altogether. Every item for the service is now read and the unexpired one with the furthest deadline wins, falling back to the plain lookup when the Keychain cannot be enumerated.

- Name a project from the working directory the session recorded instead of the folder Claude stored it under. That folder name has every `/` flattened to `-`, so one project arrived under several names — `tg/payroll-backend` and `tg-payroll-backend`, `dayshape/dayshape` and `dayshape-Dayshape` — and its spend was split between them. Every parser now shares one naming pass: a path stops at the checkout that contains it — located by its `.git`, so `spendwatch/src` is `spendwatch` while `oss/paseo-baseline` keeps both segments — worktrees collapse into the directory holding them rather than inventing a project per generated name, scratch under a hidden directory is credited to the repository around it, dated scratch to the tool that made it, every temporary directory becomes a single `/tmp` entry, a directory stamped with an epoch (one run of a tool, named afresh each time) becomes a single `~/scratch` entry, and spellings differing only in case are folded together since the filesystem never distinguished them.

- Keep an all-time spend archive rather than only the months still on disk. Each recorded month now also stores where its tokens went, so a month card shows who spent it and which projects it went to, and the History tab leads with the all-time token and cost total. `--months N` backfills as far back as the transcripts reach; a month holds the agents whose transcripts still existed when it was first recorded, which is stated on the page rather than implied.

- Reset spend with the calendar month and keep every closed month. A report covers the current month by default, `--month YYYY-MM` reads a past one, and `--days N` still gives a rolling window. The History tab lists one collapsed card per month with its tokens, estimated cost, calls, sessions, and per-machine breakdown, so an expensive August stops inflating a quiet September.
- Window turns by their own timestamp instead of the mtime of the file holding them. Sessions are found by file mtime, so resuming an old session pulled every turn it ever recorded into "the last 30 days" — a 30-day total could quietly cover 37 days of work. `--months N` now also folds several months out of a single pass, and each report records the month it belongs to so per-machine exports merge into the right one.

- Refresh the Claude OAuth token instead of waiting for a human. The access token lives eight hours and no collector host runs Claude Code, so the capacity card reliably died within a working day and only a manual `claude login` brought it back. Reads now refresh ahead of expiry, retry once after a 401, and persist the rotated credentials atomically. Credentials written without an `expiresAt` are treated as due, which is the shape that used to go stale unnoticed.
- Report why a Claude capacity read failed instead of returning an empty array. An expired token, a rate limit, and a transient fault were indistinguishable, so an account that needed re-authentication looked exactly like an account that was never configured. `capacity-current --provider claude` now names the reason on stderr, and an expired token raises the existing sign-in banner rather than letting the card drift into "Not current".
- Fall back to the macOS Keychain when `~/.claude/.credentials.json` is present but blank. Claude Code leaves that husk behind after moving the secret to the Keychain, and preferring the file whenever it merely existed dropped the account with no usable token and no explanation.
- Show Grok on the capacity dashboard after the Lokai routes. Grok Build reports no quota and no balance, so the card reports what was sent over a rolling 24 hours and 30 days, priced at published list rates as an API-equivalent estimate rather than billed money, and stays out of the utilization planner.
- Track Grok CLI spend alongside Claude Code and Codex: read `~/.grok/sessions/**/updates.jsonl`, attribute tokens to the prompt that caused them, and break the run down by tool, shell command, project, and model. `~/.grok-*` profiles and the account email are picked up automatically, and `spendwatch account add grok --name <profile>` connects another one.
- Read live Claude capacity through the account's own OAuth usage endpoint (`capacity-current --provider claude`), removing the third-party menu-bar dependency that could silently freeze Claude windows on an old snapshot.
- Measure the recent burn rate inside the current quota cycle and compare it with the rate the remaining allowance affords, so a burst is visible while there is still time to slow down. Each window now shows its pace, its budget multiple, and how long before the reset it runs out at that rate.
- Never present an expired or unrefreshed quota sample as current capacity: the dashboard labels it "Cycle ended" or "Not current" with the last reading and its age, the terminal summary matches, the utilization planner stops pacing it, and `guard` returns `unknown` instead of `ok`.

- Fill the Copilot budget track solid red once the monthly ceiling is passed instead of draining it to an empty line.
- Report Copilot overspend past the monthly ceiling instead of clamping it, and alert on the monthly credit budget at the same 30/15/10/5/0 steps as weekly quota.
- Pace Copilot against a manual monthly ceiling of 40,000 AI credits for $400 ($0.01 per credit, overridable) and drop the per-seat shared-pool and promotion maths.
- Remove the private dashboard hostname from the public Chrome extension, add origin-scoped URL configuration, and enable repository security automation.
- Add a 90% utilization planner for subscription-backed capacity, excluding PAYG API balances from subscription sizing.
- Match Chrome's native dark bookmark bar and menu typography, sizing, colors, and surfaces.
- Show the Chrome profile's Bookmark Bar on the extension New Tab page.
- Add a self-recovering Chrome New Tab extension for the private capacity dashboard.
- Hide the alert test control after the first verified push delivery.
- Show provider-aware sign-in links when a collector reports expired authentication.
